# Демонстрация, API и интеграции

## Сценарий защиты, 5–7 минут

1. Показать источник задания, причину замены YAT-19, конкретную версию внешнего корпуса, фактическое число страниц и распределение классов.
2. Объяснить разметку и group split, показать сложный пример с двумя перекрывающимися классами.
3. Запустить UI на проверенном model bundle, загрузить страницу, получить рамки, confidence, время и JSON.
4. Показать negative страницу с пустым списком и корректную ошибку для повреждённого файла.
5. Показать реальный сложный FN/FP, таблицу экспериментов, поклассовые test метрики и ограничения.
6. Скачать JSON/overlay и объяснить будущий адаптер СЭД/OCR.

Подготовить 8–12 разрешённых примеров: оба класса вместе, каждый отдельно, негатив, бледная печать, маленькая подпись, край страницы, перекрытие, ошибка модели. Отмечать, какие из test; не выбирать по ним модель. Для воспроизводимого демо хранить manifest примеров и hash bundle. Запись/скриншоты — резерв на случай отсутствия GPU; заранее вычисленный результат явно обозначать как сохранённый, не выдавать за живой запуск.

## UI

Одна страница: загрузка изображения, preview, кнопка анализа, статус, overlay с разными цветами классов и легендой, список объектов, threshold для отображения, скачивание JSON/PNG, версия модели. Не включать обучение в интерфейс MVP. При смене threshold переиспользовать исходные confidence или объяснить повторный inference; не изменять эталонные метрики. Ошибки показывать понятным текстом без traceback и файловых путей сервера.

## Контракт API v1 (план реализации)

- GET /healthz: процесс жив, 200; не загружает модель повторно.
- GET /readyz: 200 только после загрузки совместимого bundle, иначе 503.
- GET /v1/model: версия, классы, ограничения, preprocess; без локальных секретных путей.
- POST /v1/predict: multipart file, опциональные threshold_stamp/threshold_signature в [0,1]. Один файл — одна страница. Без параметров используются bundle thresholds.
- Успех 200: объект schemas/prediction.schema.json. bbox_xyxy в пикселях нормализованного исходного изображения, origin top-left; x2/y2 — исключающие границы. Confidence — score детектора, не вероятность подлинности.
- Ошибки: 413 лимит, 415 формат, 422 повреждённое изображение/параметры, 503 модель недоступна или занято, 504 timeout, 500 внутренняя ошибка. JSON error={code,message,request_id}; не отдавать stack trace. Реальную latency измерять, исходный файл не включать в ответ.

Пример без утверждения о реальном предсказании:

```json
{"schema_version":"1.0","request_id":"demo-example","model_version":"candidate-001","image":{"width":1000,"height":1400},"detections":[{"class_id":0,"label":"stamp","confidence":0.91,"bbox_xyxy":[100,200,250,350]}],"timing_ms":{"preprocess":12,"inference":90,"postprocess":5}}
```

Проверка x1<x2≤width и y1<y2≤height, совпадения class_id/label выполняется runtime validator; JSON Schema не выражает все межполевые ограничения.

## Локальный и контейнерный запуск

При реализации зафиксировать Python/зависимости в lock, Docker base image и digest, порт API и UI, mount read-only model bundle. CPU образ — основной переносимый; GPU профиль отдельный и проверяется на совместимости driver/CUDA. Compose запускает API и UI, проверяет readiness. Веса получают отдельно по URL/hash до старта. Не скачивать неизвестную модель при первом пользовательском запросе. Для офлайн защиты заранее проверить загрузку всех артефактов без сети.

Будущие команды в README должны быть скопированы с реально проверенного запуска; сейчас docker-compose и сервер отсутствуют. Секреты через environment, .env не коммитить. По умолчанию bind localhost; при удалённом доступе нужны TLS, аутентификация, rate limits и политика хранения. Перед открытием сервиса внешней сети выполнить эти требования.

## Путь интеграций

1. CLI batch для локальной обработки каталога: одна строка JSONL на страницу, exit code и журнал неуспехов; исходные документы не изменять.
2. OCR pipeline: потребляет bbox в тех же координатах, получает crops с описанным padding; OCR результатов не добавлять в исходные классы детектора.
3. PDF adapter: renderer с фиксированными DPI, page_index и affine transform; лимиты страниц, encrypted/повреждённые PDF, безопасный parser.
4. СЭД: внешний адаптер получает document_id и файл, отправляет результат с schema/model version; решение об утверждении документа принимает бизнес-система/человек.
5. Async jobs при реальном объёме: POST /v1/jobs→202/job_id, GET status/result, Idempotency-Key в пределах tenant, TTL, retries с backoff и dead-letter, подписанный webhook по allowlist с защитой от SSRF. Это будущий контракт, отсутствующий в MVP.
6. ONNX/другой backend: сравнить с PyTorch на фиксированном наборе, задать допустимые численные отклонения и влияние на AP до замены.

Наблюдаемость: request_id, model_version, размеры, статус, latency, количество объектов; без байтов/текста/имён загруженных документов. Контроль дрейфа — агрегаты, выборочная ручная проверка с правом доступа; новые данные не дообучают модель автоматически. Версия схемы меняется при несовместимости, старые consumers получают переходный период.
