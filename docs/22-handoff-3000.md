# Передача работы по SealSign и продолжение набора на 3 000 страниц

Актуальная отправная точка — ветка `work`, коммит `f154da9` или более новый
коммит этой ветки. Перед началом прочитать `AGENTS.md`, `docs/08-decisions.md`,
`docs/11-product-development-plan.md` и конец `templates/implementation-status.md`.
Журнал содержит историю решений: не все исторические требования остаются действующими.

## Что перенести вне GitHub

Скопировать всю локальную папку `artifacts/` из корня текущего репозитория в
корень клона на компьютере друга. Сохранить имена и структуру вложенных каталогов.
Размер на момент передачи — около 7,2 GiB; часть файлов — промежуточные копии.
Передавать через защищённое хранилище или накопитель, доступный только команде:
права на отдельные исходные документы не подтверждены, могут встречаться
персональные данные. Не размещать архивы или документы в публичном репозитории.

Важнейшие части переноса:

- `artifacts/data-audit/mapo80/` — три исходных ZIP и метаданные источника;
- `artifacts/data-qc/s04-3000-review-v2/queue.json` — фактическая очередь кандидатов;
- `artifacts/data-qc/background-audit-v2/` и `background-group-review-v1/` —
  аудит повторов, очередь компонент, решения и межкомпонентные связи;
- `artifacts/data-qc/batch001-agent/` и `artifacts/annotation-batches/` —
  предыдущие группировки и версии разметки;
- `artifacts/data-qc/s04-teaching-v1/` — предыдущий учебный split, его test и экспорт;
- `artifacts/data-audit/exports/`, `artifacts/data-import/` и остальные каталоги —
  исходные выгрузки, пилоты, предыдущие проверки и их промежуточные материалы.

Для полной передачи копировать всю папку; отдельного архива из неё создавать
необязательно. `.venv`, ключи, пароли, `.env`, веса и учётные записи передавать
не нужно. Доступ к GitHub и к вычислительной среде каждый участник настраивает
своими средствами. При 7,2 GiB входных данных нужен дополнительный свободный
объём для установки ML-зависимостей, промежуточных данных и результатов;
конкретный объём зависит от выбранного обучения.

## Клонирование и проверка на Windows

Установить Git и `uv`; открыть PowerShell в папке, где должен находиться проект:

```powershell
git clone --branch work https://github.com/chrtxachok/SealSign.git
Set-Location SealSign
```

Затем скопировать `artifacts` в текущую папку `SealSign`, чтобы, например,
существовал `artifacts\data-audit\mapo80\train.zip`. Если клон уже есть,
сначала проверить `git status` и не затирать чужие локальные изменения; затем
получить актуальную ветку обычным способом работы команды.

Проверить SHA-256 ключевых файлов (`Get-FileHash` возвращает хеш в верхнем
регистре — регистр для сравнения значения не важен):

```powershell
Get-FileHash artifacts\data-audit\mapo80\train.zip
Get-FileHash artifacts\data-audit\mapo80\val.zip
Get-FileHash artifacts\data-audit\mapo80\test.zip
Get-FileHash artifacts\data-qc\s04-3000-review-v2\queue.json
Get-FileHash artifacts\data-qc\s04-teaching-v1\split.json
Get-FileHash artifacts\annotation-batches\batch-001-agent-v7\manifest.jsonl
Get-FileHash artifacts\annotation-batches\batch-001-agent-v7\annotations.json
```

## Текущее состояние и следующие шаги

1. В приватном `queue.json` выбраны **3 000 кандидатов**, не 3 000 проверенных
   и размеченных страниц. В источнике есть рамки печатей, но подписи не размечены
   как класс. Наличие имени `neg` не подтверждает отсутствие целевых объектов.
2. Доразмечать и проверять обе категории порциями, сохраняя исходные версии,
   решения, статусы и контрольные суммы. 12 кандидатов совпадают с учебными
   train/val и могут иметь полезную ранее сделанную разметку; перенос следует
   отдельно проверить. Не изменять и не использовать прежний test для настройки.
3. Проверять принадлежность страниц к группам документов и повторов; очередь
   исключает известные связи с прежним test, но может не содержать все связи.
   Только после QC зафиксировать состав и новый групповой split. Не считать
   пустые или непроверенные подписи отрицательными примерами.
4. Подготовить среду обучения, запустить сначала короткий проверочный эксперимент,
   затем обучение; измерять качество и выбирать параметры по val, test оставить
   для финальной оценки. До запуска обучение и качество модели не подтверждены.
5. Обновлять журнал, результаты и инструкции запуска. Данные, веса, приватные
   документы и секреты в GitHub не коммитить. Большие веса при необходимости
   разместить отдельно после проверки условий доступа, указать ссылку и хеш.

Прежний набор на 63 страницы — ограниченная учебная версия S04, а не результат
новой цели 3 000. Валидация в ней содержит всего три рамки подписей; качество
оценки будет нестабильным. Первоначальные лицензии исходных документов полностью
не проверены; примеры не публиковать без проверки прав и персональных данных.
