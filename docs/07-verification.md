# План проверок и приёмки

Проверять смысловые риски: ошибки классов, геометрии и утечки данных. Документационный этап не требует фиктивных unit-тестов будущего кода. Сейчас проверяются ссылки, JSON, структура и согласованность контрактов.

| Проверка | Доказательство | Блокирует |
|---|---|---|
| Полнота исходного корпуса | N строк manifest = фактический объём версии; checksum, исключения; отклонение от исходных 5 000 раскрыто | обучение |
| Корректность bbox/class | validator report, визуальная выборка | обучение |
| negatives не unreviewed | QC журнал и coverage | обучение |
| Split без leakage | group intersections=0; hashes; near-duplicate review | сравнение метрик |
| Геометрия resize/letterbox | round-trip на краях и non-square изображениях | inference |
| Перекрывающиеся классы | NMS сохраняет stamp и signature | inference |
| Tile remap/merge | объект на стыке и без двойного учёта | включение tiling |
| E00 overfit | кривые и визуальные предсказания | полный baseline |
| Метрики | идеальное предсказание, пропуск, FP, неверный класс на toy examples | финальный test |
| Model bundle | hash, class mapping, версия, CPU load | demo |
| API | valid/negative/corrupt/oversized/unready; schema validation | demo |
| Конфиденциальность | нет сырых файлов в logs, temp cleanup при исключении | удалённое demo |
| Чистое окружение | README воспроизведён другим участником | сдача |

Геометрические тесты должны включать EXIF, padding, scale, пустой результат, несколько объектов, координаты у границы. Метрики на toy examples проверяют evaluator, не качество модели. Для CPU/GPU сравнения использовать разумный численный допуск, а не bit equality.

## Итоговая приёмка

Приложить паспорт внешних данных и URL фиксированной версии, annotation/split version, конфигурации и lock, перечень опытов с фактами, final metrics JSON/CSV, hashes весов и доступную ссылку, разрешённую галерею, протокол latency с оборудованием, отчёт по принятому шаблону ГОСТ и реальный вклад каждого. Проверить отсутствие ZIP/весов/секретов в Git и доступность ссылок для преподавателя.

Если цель качества не достигнута, честно показать измерения, причины и дальнейший план. Обязательная оценка и корректный протокол не подменяются демонстрацией лучших страниц. Проверить трассировку всех SRC из docs/00; отметить оставшиеся ограничения.
