# Локальный редактор пилота

Подготовлен переносимый редактор bbox для текущего пилота из 50 train-страниц
mapo80. Все изображения и исходные stamp bbox встроены в HTML. Отправка данных
во внешние сервисы, модель и сервер для сохранения не используются. Это инструмент
первого просмотра, а не закрытие S04. Большой корпус нужно разбивать на партии;
сборщик ограничивает вход 200 страницами и 150 MiB изображений.

## Работа на Windows

Приватный архив находится в `artifacts/annotation-editor/mapo80-editor-pilot50.zip`.
Скачайте его, распакуйте и откройте `editor.html` в Chrome или Edge. Если браузер
запрещает file://, откройте терминал в распакованной папке и выполните:

```powershell
py -m http.server 8765 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8765/editor.html . Эта команда Windows не выполнялась
в облачной среде; эквивалентный запуск Python HTTP server проверен на Linux.

1. Укажите проверяющего. Просматривайте страницу целиком; исходные bbox не
   считаются правильными автоматически.
2. Выберите «Подпись» или «Печать» и протяните рамку мышью. Красный = печать,
   синий = подпись. Масштаб регулируется ползунком; страницу можно прокручивать.
3. Выберите рамку в списке, чтобы изменить класс/координаты или удалить её.
   x/y/width/height — пиксели нормализованного изображения. Рамки за краем,
   нулевая площадь и повторы при применении координат/экспорте отклоняются.
4. После полного просмотра обоих классов поставьте две галочки и нажмите
   «Отметить просмотр страницы». При правке статус снова становится unreviewed.
   Отсутствие объектов тоже требует просмотра, а не пустого label.
5. Регулярно нажимайте «Скачать правки JSON». Автосохранение действует только
   в текущем браузере/профиле; перенос HTML, очистка хранилища или инкогнито могут
   лишить доступа к нему. При ошибке локального сохранения появляется сообщение.
6. Для продолжения загрузите сохранённый JSON кнопкой «Загрузить правки».
   Файл проверяется по хешам manifest/аннотаций, составу страниц, размерам и bbox;
   замена текущих правок требует явного подтверждения в интерфейсе.
7. Передайте скачанный JSON для проверки и последующего применения в отдельной
   версии данных. Исходные аннотации/изображения этим редактором не изменяются.

Нумерация здесь соответствует порядку manifest пилота, а не CSV предыдущих
перемешанных review-архивов. Идентичность обеспечивают page_id и checksum PNG;
номера между разными пилотами нельзя переносить напрямую.

## Воспроизведение

Из корня checkout после установки зависимостей из uv.lock:

```console
.venv/bin/python scripts/build_annotation_editor.py artifacts/data-import/mapo80-pilot50-v1 --output artifacts/annotation-editor/mapo80-pilot50.html
.venv/bin/python scripts/validate_annotation_review.py artifacts/data-import/mapo80-pilot50-v1 path/to/sealsign-review.json
```

Первая команда исполнена: 50 страниц, 38 145 604 байта HTML. Существующий файл
не перезаписывается. Путь review во второй команде — пример: фактически проверен
отдельный синтетический browser-smoke export в /tmp, не человеческая разметка.
Экспорт содержит schema sealsign-review-v1, source hashes и PNG hashes, reviewer,
объекты с category_id 0/1 и pixel xywh, флаги просмотра и notes. Все exports имеют
accepted_for_training=false; first_review не заменяет независимый второй QC.
Валидатор не применяет JSON в corpus и не одобряет обучение. Проверка всех
подписей и печатей, доразметка, source rights и group split остаются обязательными.

## Проверки

В headless Chromium реально проверены рисование подписи, обе галочки/проверяющий,
отказ bbox за границей, автосохранение после reload, JSON export, удаление рамки,
загрузка export и отсутствие page errors. В облачном Chromium file:// запрещён
администратором, поэтому использовался loopback HTTP. Режим file:// на Windows
не проверялся. Браузерная проверка проводилась в изолированном временном профиле;
нарисованная тестовая bbox не попадает в исходный HTML или corpus.

Python tests проверяют привязку к source hashes, отсутствие пропущенных страниц,
геометрию и невозможность обозначить first_review без просмотра обоих классов.
Данные, HTML с документами, ZIP и screenshots остаются под gitignored artifacts/;
в Git только шаблон интерфейса, сборщик, валидатор и документация.
