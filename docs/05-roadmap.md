# План реализации и задания агентам

Конкретный порядок реализации и критерии S01–S12 — [пошаговый план](11-product-development-plan.md); готовый prompt — [инструкция постановки задач](12-agent-execution-guide.md).

Актуальный календарь до 19.11.2026 — docs/10-two-week-execution.md; подбор внешнего корпуса — docs/09-dataset-research.md.

План зависит от доступности внешних данных, разметчиков и фактического VRAM RTX 4070. Оценки ниже — активные рабочие дни для команды из трёх человек, не обещание календарной даты. Разметка оценивается отдельно: время = N × медиана минут просмотра страницы / 60 + QC; измерить на пилоте, не предполагать, что negatives бесплатны.

## Пакеты задач для исполнителей

**TASK-01 / данные.** Вход: URL/revision архива, docs/03. Выход: inventory CLI, manifest schema, архивный паспорт, безопасный importer, тесты повреждения и path traversal. Не скачивать все кандидаты без оценки размера. Done: все страницы учтены и checksum проверяем.

**TASK-02 / разметка.** Вход: пилот и инструкция. Выход: проект инструмента, конвертер COCO→YOLO с явным class mapping, QC журнал, статистика, фиксированные groups/splits. Done: round-trip координат проверен, negatives подтверждены, нет межчастных дублей. Владение разметкой и спорными объектами остаётся у людей.

**TASK-03 / обучение.** Вход: принятый split, configs. Выход: train/evaluate команды, lock, логи, effective config, experiments.csv, model card. Done: E00/E01 повторены и результаты реальные. Test не используется для выбора.

**TASK-04 / инференс.** Вход: bundle contract, schema v1. Выход: Predictor, CLI, преобразования, экспорт JSON/overlay. Done: тесты letterbox/remap, пустой результат, перекрытие разных классов, CPU mode. Никаких случайных mock рамок в основном пути.

**TASK-05 / API и демо.** Вход: TASK-04. Выход: FastAPI, Streamlit client, health/readiness, лимиты, ошибки, контейнеризация. Done: загрузка файла→реальная модель→JSON→overlay и очистка файлов проверены.

**TASK-06 / приёмка и отчёт.** Вход: все артефакты. Выход: final test results, error gallery, ГОСТ-отчёт, вклад команды, проверенный README. Done: чистый запуск по README, проверенные ссылки и checksum.

## Порядок работы ИИ-агента

Прочитать AGENTS.md, источник, профильный документ и открытые решения. Указать задачу, входы, критерии Done; не выдавать незакрытую зависимость за готовую. Каждый PR/коммит должен описывать конкретный результат и проверку. Менять контракты вместе со схемами, примерами и потребителями. Ресурсоёмкое обучение согласовать по фактическому бюджету; сетевые публикации данных не подразумеваются разрешёнными.

Внутри команды предложить владельцев направлений «данные/QC», «обучение/оценка», «сервис/демо»; распределение между Маланином, Солдатовым и Клёсовым подтверждает команда. Не придумывать персональные вклады. Фиксировать реальные задачи и коммиты в журнале.

## Минимальный объём при ограниченном сроке

Сохраняются зафиксированный внешний корпус, два класса, полная проверенная разметка используемых страниц, корректный split, один обученный baseline, измеренная оценка, CLI, простое демо и отчёт. Дополнительные архитектуры, ONNX, PDF и асинхронные jobs переносятся. Пользователь разрешил замену YAT-19; итоговое количество реальных страниц и отличие от исходного объёма должны быть явно записаны. Не утверждать, что преподаватель уже согласовал изменение.
