# Проверка повторных исходных фонов

`scripts/audit_backgrounds.py` ищет кандидатов одного документа под разными
печатями, включая пары внутри одного исходного split. Он не меняет manifest,
аннотации, группы или split и не разрешает обучение. Базовая среда — uv.lock,
Python 3.12/Pillow 13; дополнительные зависимости не нужны.

Проверенная команда из корня репозитория:

```console
.venv/bin/python scripts/audit_backgrounds.py artifacts/data-audit/mapo80/train.zip artifacts/data-audit/mapo80/val.zip artifacts/data-audit/mapo80/test.zip --output artifacts/data-qc/background-audit-v2
```

Существующий output запрещён: для повторного запуска выбрать новый каталог.
ZIP inventory проверяет пути/повторы/symlink и бюджет распаковки; отдельно
ограничены размеры изображений/labels и пиксели, проверены bbox и EXIF.
Результат публикуется из временного каталога после успешного завершения.

Изображение приводится к grayscale 128×128 без поворота или регистрации.
Исходные stamp bbox расширяются на 2px в этом масштабе и маскируются.
Для 16 позиционных блоков 32×32 вычисляются локальные 64-битные average hashes;
малоконтрастные, почти пустые и сильно закрытые маской блоки пропускаются.
Кандидаты с минимум 4 одинаковыми хешами проходят проверку видимого фона:
минимум 50% площади, минимум 128 тёмных пикселей в каждой странице, минимум 85%
пикселей с разницей≤12 и IoU тёмных пикселей≥0.70. Порог тёмного пикселя<200.
Чрезмерно частые buckets>200 страниц исключаются с явным счётчиком. Все
параметры фиксированы в скрипте и отчёте; после просмотра пар не менялись.

## Результат полного прогона

Все 7854 файла фиксированной ревизии обработаны,7666 имеют минимум 4 активных
блока.18414 пар прошли предварительный поиск,16776 прошли сравнение фона;
5514 из них между исходными ZIP/split. Частых исключённых buckets нет.
Агрегаты: [background-candidate-audit.json](../reports/data/background-candidate-audit.json).
Полный приватный CSV сохранён без ограничения числа пар в artifacts/data-qc/.

Кандидатный граф охватывает 4040 файлов в 583 связных компонентах. Это **не
проверенные группы**: ложное ребро может ошибочно объединить несколько документов.
Если бы каждая компонента оказалась одним оригиналом, получилось бы 4397 фонов
вместо 7854 файлов — до прочих исключений. Это условный сценарий, не установленное
число оригиналов. Минимум 5000 по этим результатам не подтверждается и не опровергается.

Все 4 ранее визуально проверенные train-пары партии 001 найдены алгоритмом;
это диагностическая проверка на известных примерах, не независимая оценка recall.
Дополнительно выбраны 8 train/train пар из разных компонент, seed42. Во всех 8
визуально совпали содержание и индивидуальные детали документа при разных
печатях/масштабе. Вывод относится только к этим 8 парам, не ко всем компонентам.
Приватный журнал с объяснениями/путями и контактными листами остаётся в artifacts/;
в Git [агрегат просмотра](../reports/data/background-visual-sample.json).

Первый полный прогон с Python-циклом и повторный прогон с ImageChops дали
побайтово одинаковые CSV и inventory и равные отчёты. Критерии не менялись.
Доказательство: [background-comparison-parity.json](../reports/data/background-comparison-parity.json).
Тесты проверяют разные печати на одном фоне, ложное совпадение белого пространства,
разный текст, чрезмерное маскирование и небезопасный/неполный ZIP. Полный pytest:
68 passed; ruff check/format прошли.

Ограничения: сдвиги/повороты/обрезки/повторные сканы могут быть пропущены;
похожий шаблон может пройти фильтр; исходные stamp labels неполны, подписи не
маскируются. Изображения и labels исходных val/test обработаны только для поиска
возможных пересечений; новой визуальной разметки test и настройки модели нет.
Далее нужны визуальное разрешение кандидатных групп, проверка происхождения
компонентов, полный двухклассовый QC и новый group split. S04 не завершён.

## Разрешение крупных кандидатных групп

Проверены все 130 файлов шести крупнейших компонент (при равном размере —
порядок стабильного component_id). Это целевой просмотр крупных групп, а не
случайная выборка для оценки доли дублей во всём корпусе. Использованы обзорные
листы всех членов, увеличенные адресные/датирующие поля и идентификаторы.

Самая большая компонента из 32 файлов содержит два разных письма общего шаблона:
21 вариант одного адресата и 11 другого; различаются адресаты, комнаты,
обращения и архивные номера. Её нельзя считать одним оригиналом. Для будущего
split у этих двух оригиналов сохраняется общая семья шаблона. Остальные пять
компонент соответствуют пяти визуально различным исходным документам.

Итого в просмотренном подмножестве семь фоновых документов и 123 дополнительных
варианта. Все семь групп пересекают исходные ZIP/split. Из 1272 кандидатных
рёбер внутри этих компонент 130 соединяют два разных оригинала. Это доказанный
пример ложного объединения по общему шаблону, не показатель ошибки всего графа.
Остальные 577 компонент не разрешены. Глобальное число оригиналов не установлено.

Журнал решений привязан к SHA-256 report.json,inventory.json,candidate-pairs.csv.
`scripts/validate_background_review.py` проверяет точное покрытие каждой
рассмотренной компоненты: никакой член не пропущен, не назначен дважды и не
перенесён из другой компоненты. Разделение компоненты на несколько оригиналов
поддерживается явно. Evidence и reviewer обязательны, но валидатор не проверяет
истинность визуального решения и не присваивает приёмку/QC/split автоматически.

Проверенная команда:

```console
.venv/bin/python scripts/validate_background_review.py artifacts/data-qc/background-audit-v2 artifacts/data-qc/background-group-review-v1/review-v2.json
```

Приватный background-registry-v1.json разделяет background_id и предлагаемую
семью утечки; в canonical manifest группы не применены. Журнал с путями и
изображения только в artifacts/. В Git —
[background-group-review.json](../reports/data/background-group-review.json).
Изображения upstream val/test просмотрены только для установления идентичности
документов и возможной утечки; рамки и параметры модели не выбирались.
Полная проверка:75 passed,ruff check/format успешны.
