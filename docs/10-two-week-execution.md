## RTX 4070 — основная среда

Сначала узнать ОС, точный объём VRAM, свободные диск/RAM. Не предполагать, что любая 4070 имеет одинаковый VRAM (desktop/mobile различаются). Предпочтительно Linux/WSL2; native Windows допустим после проверки wheel/paths/workers. Зафиксировать драйвер, Python и CUDA-совместимую сборку PyTorch. Команда `nvidia-smi` и проверка `torch.cuda.is_available()` должны выполняться на компьютере пользователя, не в текущей облачной среде вместо него.

Стартовать small model, imgsz=1024, batch=4, AMP после проверки стабильности; при OOM уменьшить batch до 2/1, а затем разрешение, с отдельной записью конфигурации. Подбирать workers по платформе, не копировать завышенное значение. Сохранять best/last после каждой эпохи; оценить время 1–3 эпох и прогноз полного опыта до ночного запуска. Сохранять эксперимент и окружение вместе; при resume не пересоздавать split.

Данные распаковать локально в быстрый диск; не читать каждое изображение через сетевой диск. Веса и manifest передаются отдельно с hash, секреты не коммитятся. Доступ к компьютеру пользователя ещё не предоставлен, обучение на нём в рамках этой документационной задачи не выполнено.

## Google Colab — резерв

Реализация должна добавить `notebooks/train_colab.ipynb`, который вызывает тот же train entrypoint и config, а не содержит другую ML-логику. Ноутбук сейчас не создан; это задача следующего этапа.

Ячейки будущего notebook:

1. Выбор GPU runtime вручную пользователем; запись фактического accelerator/VRAM/версий.
2. Checkout конкретного Git commit и установка lock с проверкой CUDA; не `pip install -U` без фиксации.
3. Получение выбранной версии данных и весов по разрешённым URL с checksum; токены через Colab Secrets, не через публичную ячейку.
4. Mount Drive только с разрешения пользователя для хранения checkpoint; рабочий датасет копировать на локальный `/content` диск.
5. Validation manifest/split/QC, затем smoke и train через тот же CLI.
6. Периодическое копирование checkpoint, config, logs и run state в постоянное хранилище; восстановление после разрыва сессии.
7. Экспорт bundle с hash и отчёта, сравнение с локальной средой; одинаковый seed не гарантирует bit-identical CUDA результат.

Colab может прервать сессию и не гарантирует конкретную GPU/ресурсы; план не должен зависеть от непрерывной 24-часовой бесплатной сессии. Никаких автоматических обходов лимитов. Перед переключением на Colab проверить, что выбранные данные разрешены к загрузке в эту среду.

## Сокращение при нехватке времени

Первым исключить E05, ONNX, PDF, публичный deploy и асинхронную интеграцию. Сохранить полноценные аннотации двух классов, group split, один обученный baseline, честные метрики, CLI и локальное демо. Масштаб данных не увеличивать синтетическими копиями ради формального счёта. В отчёте отличать число оригиналов от числа train augmentations.
